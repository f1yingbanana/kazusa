# Kazusa Client Roadmap: Deferred Features and Their Slots

Each feature lists the extension slot it plugs into and what it depends on. None
of them should need shell changes. If one seems to, revisit the slot design in
`SKILL.md` §4 first.

| Feature                      | Slot(s)                                                                                                  | Depends on                                                                                                                                                                                                                                                   | Notes                                                                                                                                                                                                                                     |
| ---------------------------- | -------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Map renderer**             | Alternative renderer inside the `world` StageView                                                        | `places` + `parent`/`map` frontmatter, `location` domain, transit model                                                                                                                                                                                      | The place graph uses prose distances, not geography. Use an illustrated or schematic canvas with hotspots from `map: {x,y}` and an auto-layout fallback. Interpolate transit along a corridor between departure and ETA on the sim clock. |
| **Social view**              | StageView `social`; inspector section `relationships`; timeline kind `relationship.changed`              | `/kazusa/relationships?owner=&peer=` from relationship-card frontmatter (+ `quick_impression`, `open_threads`)                                                                                                                                               | Asymmetry view (A→B next to B→A), directed graph (two arcs per pair), reputation toward the player, change deltas linked to source chats.                                                                                                 |
| **Wiki view**                | StageView `wiki`; entity kind `concept`                                                                  | World Wiki + Personal Wiki read routes (frontmatter + `bodyMarkdown`)                                                                                                                                                                                        | Browse canon. Compare a character's belief against canon (Observer only). Contradiction badges.                                                                                                                                           |
| **Attention log**            | Timeline kind `attention.decided` (**built**); inspector section `attention`; presence-ring queued badge | **Built:** Perception records each decision (stimulus ids, action, source, model choice, latency score, delay, task) as uncapped entries in the `"perception"` store, read by `GET /kazusa/timeline`, and SSE `journal`. Not yet: probabilities, threshold | Answers "why didn't they reply?". In the Player lens it becomes a diegetic hint through lens selectors.                                                                                                                                   |
| **Desires at scale**         | World "Folders by: lowest desire"; Timeline `afterwards` on `task.started` rows                          | **Built:** inspector section `character.desires`, `/kazusa/desires`, SSE `desires`, `lib/time/desires.ts`. Not yet: `afterwards` in the `task.started` journal payload (Taskman would have to carry extension params) | Deliberately no per-row roster icons: desires are slow background pressure, and 300 rows of meters is noise. A folder dimension keeps it opt-in. Never derive a desire from task category.                                              |
| **Beliefs**                  | Inspector section `beliefs`; Wiki view                                                                   | Belief frontmatter (`status`, `confidence`, `claims[].evidence`)                                                                                                                                                                                             | Thought style with confidence bars. Evidence links to source chat messages.                                                                                                                                                               |
| **Agenda**                   | Inspector section `agenda`                                                                               | `MEMORY.md` `goals`/`plan` frontmatter (proposal in the contract §5)                                                                                                                                                                                         | Hard blocks versus soft goals for the current sim day.                                                                                                                                                                                    |
| **Replay / scrub**           | Timeline `tl.at` URL param → global `asOf` in the lens/source layer                                      | Journal (already sequenced); status reconstruction from journal kinds                                                                                                                                                                                        | Components render from selectors at `asOf`. Live tail pauses while scrubbing.                                                                                                                                                             |
| **Chronicle / catch-up**     | StageView `chronicle` or a Timeline mode; status item "while you were away"                              | `reflection.written` kind + daily reflection read route                                                                                                                                                                                                      | Day cards built from nightly reflections, plus auto-highlights from high-salience journal kinds.                                                                                                                                          |
| **Storyteller ticker**       | Status-bar item                                                                                          | Journal salience                                                                                                                                                                                                                                             | Rotates the latest high-salience events. Clicking opens the Timeline at that event.                                                                                                                                                       |
| **Player lens**              | `lib/lens/` selectors; lens switch in the top bar                                                        | Location, encounters, and knowledge boundaries                                                                                                                                                                                                               | Redacts private chats, thoughts and remote presence. Shows only what the player could know.                                                                                                                                               |
| **Player embodiment**        | World view actions; inspector actions for places                                                         | Spatial subsystem, travel-as-task, encounter rolls                                                                                                                                                                                                           | Choosing a destination shows a route and ETA. On arrival, encounters resolve and in-person conversations open in Chats with distinct styling.                                                                                             |
| **Observer debug**           | Inspector section `debug`; status items (cost, next wakes)                                               | Plugin routes for the `assemble()` preview, token usage, cron next-wake (read in-process)                                                                                                                                                                    | Observer only. Never shown in the Player lens.                                                                                                                                                                                            |
| **Notifications / mentions** | Top bar bell; status item                                                                                | Journal kinds that reference the player                                                                                                                                                                                                                      | "X mentioned you in a chat with Y" (Observer), or only direct events (Player).                                                                                                                                                            |

Before building any row:

1. Add its schemas to `@kazusa/client`.
2. Add a domain with `http` + `mock` sources.
3. Register its slots.
4. Record the backend ask in `backend-contract.md`.
5. Move the row from this table into `SKILL.md` §1 "First draft" once it ships.
